# Releasing TTNS FM to the Roku store

This channel is a public companion app: live radio, listings, no login, no payments. You still need a **Roku developer account that belongs to TTNS**, a **signing key**, and a **signed `.pkg`**. Nothing in this repo is a Channel Store secret.

Official docs:

- [App publishing](https://developer.roku.com/dev/docs/channel-publishing-guide)
- [Packaging](https://developer.roku.com/dev/docs/packaging-channels)
- [Certification](https://developer.roku.com/dev/docs/certification)
- [Manifest](https://developer.roku.com/dev/docs/channel-manifest)

There are two different “betas”:

| Name | What it is |
|---|---|
| **This git tag** (`v0.2.0-beta`) | The sideloadable living-room build. |
| **Roku Dashboard beta** | A 120-day, 20-user test listing. Instant publish, no certification. Not searchable in the store. |

A **public Streaming Store** listing is a separate Dashboard app. It must pass Static Analysis, App Behavior Analysis (for free apps), and Roku review. Publishing cannot be scheduled on Fridays or weekends.

Use the TTNS / organisation Roku account as the **root** owner. If a contractor publishes under their own account, they own the channel.

## 1. Developer account and device

1. Create or sign in at [developer.roku.com](https://developer.roku.com).
2. Sign that Roku into the **same** Roku account as the Developer Dashboard (the organisation that owns TTNS). A box signed into a personal account will package under the wrong Dev ID.
3. Enable developer mode: **Settings → System → Advanced system settings → Developer**. Note the device IP and the **device** installer password (this is `ROKU_DEV_PASSWORD`, not the packaging password).
4. Confirm the box can reach the internet. Packaging talks to Roku’s signing service.

## 2. Generate a signing key (once per channel)

The Packager page stays grey until the box has a key.

```bash
telnet <roku-ip> 8080
```

At the prompt type `genkey` and wait. Write down **both**:

- Developer ID (Dev ID)
- Packaging password

Put the password in `.env` as `ROKU_SIGN_PASSWORD`. Do not commit `.env`. Keep the Dev ID next to this repo so future updates use the **same** key — a new key orphans registry data (remembered station) on installed boxes.

If you later get a new developer Roku, **rekey** it from an existing `.pkg` plus this password on the installer **Utilities** page. Do not run `genkey` again for an update.

## 3. Sideload, then package

```bash
set -a && source .env && set +a
make sideload
make package
```

`make package` posts to `http://<roku-ip>/plugin_package`. Then open `http://<roku-ip>` in a browser, open **Packager**, and download the purple `.pkg` link. Store that file somewhere safe (not this git repo — `*.pkg` is gitignored).

Check the Packager Dev ID matches the `genkey` Dev ID before you upload.

## 5. Create a Dashboard app

In the Developer Dashboard: **Beta apps** or **Public apps** → **Create app**.

Suggested fields for TTNS:

| Field | Suggested value |
|---|---|
| App name | `TTNS FM` (max 30 characters, no “Roku” in the name) |
| App type | **Audio** (live radio). Not Video, not Game. |
| Monetization | **I will not be monetizing my app.** |
| Customers sign in? | **No** |
| Made for kids? | **No** |
| Category | Music, or the closest audio / local-info category the form offers |
| Domestic region | United Kingdom |
| Store countries | Start with **United Kingdom**. Add others only where you have the rights to the streams and listings. |
| Learn more URL | `https://www.ttns.fm` |
| Privacy policy / terms | The live URLs from ttns.fm (the form will not accept empty) |
| Support email / phone | TTNS public support contacts |
| Vanity access code | e.g. `TTNSFM` (max 20 alphanumeric) |

On-device description (300 characters) and online description (1,500) should say: live Brighton + national radio, local gigs and community board, tickets and sign-up stay on the website, no login.

Upload the 540×405 poster and the screenshots under **Store Assets**.

## 6. Dashboard beta (optional, 20 people)

Use this if you want friends / presenters on real boxes without enabling developer mode.

- Upload the `.pkg` under **App package**.
- Version: `0.2.0` (or whatever you type; Dashboard version is independent of `manifest`).
- Minimum firmware: **8.0** or higher if you package as squashfs; otherwise pick the format’s floor. This channel is SceneGraph on OS 15 in the living room; 9.2+ is a safe floor if the form allows it.
- Click **Publish**. No certification.
- Send testers the **access code** URL from the app page.
- Limits: 20 installs, 120 days, 10 beta apps per account. Re-upload a new `.pkg` signed with the **same** key to update testers in place.

This is the lowest-friction “release” from `v0.2.0-beta`.

## 7. Public Streaming Store (the actual store)

Do this only when you want anyone to find **TTNS FM** in Search.

1. Create a **Public** app (do not convert a leftover contractor app).
2. Fill listing, profile, monetization, contacts, privacy / terms.
3. Upload the same-key `.pkg`.
4. Run **Static Analysis**. Fix every **Error**. Treat warnings as soon-to-be errors.
5. Free apps also run **App Behavior Analysis**.
6. Tick the publishing checklist confirmations.
7. **Schedule Publish**. Earliest slot is five minutes out; not Friday/weekend.

Roku then reviews. Expect a few days, and expect a bounce if certification items below are still open.

## 8. Certification gaps in this beta

These are the likely public-store blockers. A Dashboard beta can skip them.

1. **`AppLaunchComplete` beacon** — Behavior Analysis wants the app to signal a usable UI quickly. This build does not fire it yet.
2. **Deep linking** — `supports_input_launch=1` is in the `manifest`, but `Main()` does not handle launch args. Roku says parameters are required unless the app is a **single live feed**. We have two live streams plus gigs / community, so expect to add at least station or “listen” deep links before a public submit.
3. **Deep-link test rows** in the Dashboard — one set per media type you declare.
4. **Screenshots** — six real 1920×1080 frames, no developer overlay.
5. **Privacy policy and terms URLs** that load.
6. **Same signing key** on every update after the first public package.
7. **No login / no Roku Pay** — keep monetization on “not monetizing”. Tickets stay on the website; do not add in-channel checkout.
8. Optional later: Roku Search feed and home-banner deep links if you want promotions.

Do not upload a `.zip` of this repo to the store. Upload the encrypted `.pkg` from the developer box.

## 9. After it is live

- Increment `manifest` `build_version` (and `AppVersion()` in `source/config.brs`) on every store upload.
- Sideload → package with the **saved** key → replace the `.pkg` on the same Dashboard app.
- Keep `genkey` password offline. Losing it means you cannot update the published channel without users losing registry (station memory).
